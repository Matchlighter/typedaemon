# TypeDaemon dashboard

Vite + React (class components, `@matchlighter/meta_components`) + MobX. Built to `../dist/dashboard`, served by the HTTP plugin at `/` (WS at `/ws`). All URLs relative (HA Ingress).

- `yarn build` (root) builds everything; `yarn --cwd dashboard test|typecheck|dev` (dev proxies `/ws` to :8099).
- **Add a topic**: type it in `../src/dashboard/protocol.ts` (`TopicMap`); server: `dashboardTopics.register('name', { snapshot, subscribe })` (`src/dashboard/server.ts`, see `system_topic.ts`); client: `new TopicStore(app.connection, 'name', params)` as a `@store` field (see `views/Overview.tsx`) or `app.connection.subscribe(...)` + `dispose()`. Default delta = shallow merge; pass `applyDelta` otherwise. Sub status: `syncing | live | stale | error`.
- **Add a view**: edit its entry in `src/routes.tsx` (route = first hash segment; rest via `app.route.segments/query`).
- **Add an action** (one-shot command): type it in `ActionMap` (`protocol.ts`), `dashboardActions.register('name', handler)` (`src/dashboard/server.ts`); client: `await app.connection.call('name', params)` (rejects with the server's message; resolves with the handler's return value if the action is listed in `ActionResultMap`, e.g. `storage.value`).
- **Add an app detail tab**: edit its entry in `src/views/app_tabs.tsx` (`render`, optional `count`/`flag`, fed by `AppDetail.counts` from `src/dashboard/hypervisor_app_detail_source.ts`). Tab = `#/apps/<id>/<key>`; header, tab bar, error panel and routing are done for you.
- **Orphan apps** (left the config, operating dir remains): `#/apps/<id>[/leftovers|/cleanup]` shows the Apps list with `views/OrphanModal.tsx` (leftovers by type, reusing `OrphanLeftovers.tsx`; `cleanup` = confirm dialog up) instead of the app page when the `orphan` topic reports leftovers (`views/AppRoute.tsx` decides); closing returns to `#/apps`. The Apps orphan row links to those routes. Cleanup = `orphan.cleanup` action -> `Hypervisor.destroyOrphanApplication` (exclusive access, destroyers, then delete the dir; any failure keeps everything). Add a cleanup step by registering a destroyer (`DestroyerStore.defineDestroyerClass`); it must throw on failure.
- **Show entities**: per-app rows (`appEntities`) and every app's + orphans' (`entities`, `GlobalEntityRow`, built by `combinedEntitiesSource` over the per-app source) share `views/entities_model.ts` (`filterEntities`/`entityFacets`/`applyEntitiesDelta`), `EntityRow`, and the Delete-from-HA flow (`EntityDeletion` + `EntityDeleteDialog`). Long lists use `VirtualList`. See `views/Entities.tsx`.
- **Several JSON viewers on one page**: give each a `scope` (`JsonViewer`/`StorageKeyRow`) so open nodes are kept per viewer in the shared persisted state (`scopedPath`); lazy values (`lazy(meta)`) fetch via the `loader` on expand (and again via `JsonViewState.refresh` when the source changes). See `views/AppStorageTab.tsx`.
- **Add a component**: put `Foo.gallery.tsx` (default export `GallerySection`) next to it; shows in dev-only `#/_components`.
- Theme tokens: `src/styles/tokens.css`; `data-theme` set by `ThemeStore`.
- **Class components**: decorate with `@with_meta_components` (`@withMeta` from `src/meta.ts` if the component takes props) above `@observer`, so plain class fields work and lifecycle uses `@mount_effect`/`@store` (not `componentDidMount`).
- **Interaction tests**: default vitest env is `node` (use `renderToString`); for DOM/click/keyboard tests add `// @vitest-environment happy-dom` as the first line of the test file and render with `react-dom/client` + `act`.
- **Show logs**: subscribe to the `logs` topic with `sources` (omit for every app/plugin/system) and `limit`, fold deltas with `applyLogsDelta(cap)` (`views/logs_model.ts`), and render `<LogsPanel rows state status />` (filters, search, pause/resume, jump to error, virtualized `LogList`). Keep the `LogsViewState` per view via `logsViewState(key)`. Server side, loggers created with a `source` (`createDomainLogger`) feed the `logTap` ring buffers (`src/hypervisor/log_tap.ts`). See `views/AppLogsTab.tsx`.
